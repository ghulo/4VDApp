How 4VD fits together

One installation serves many businesses. A React dashboard (also run inside the Windows app at the till) talks to one Express API on Postgres, where row security keeps each business's rows apart. Everything below except the hosting map is read from the code by generate.mjs; the same data is in architecture.json.

    Many businesses (tenancy)

      Layering rules

      • routes/ → middleware → controllers/ (zod via validators/, one service call, sendSuccess) → services/ (rules) → repositories/ (SQL through Kysely only).
      • container.ts builds every repository and service once and injects them by constructor; tests build their own with fakes.
      • Errors are AppError subclasses; answers are always { success, data, message, error, meta? }.
      • Money goes through roundMoney; books post through BooksPoster and postingRules.ts; filed VAT months are locked (periodLock.ts).
      • Every change writes an Activity entry; services/undo/ reverses it; deletes are soft (deleted_at).
